# Iron & Gold — Stage 1 (Playable Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A playable single-player 1836 game on a real world map: OpenFront-style territory, troops and attacks; buildings, goods, money, GDP, population and SoL; an AI with five difficulty levels; save/load; end date and score — installable to the iOS Home Screen and deployed to GitHub Pages.

**Architecture:** A deterministic simulation (`src/sim`, pure TypeScript, no DOM) runs inside a Web Worker and advances in ticks from serializable commands; the main thread renders the tile map with raw WebGL2, draws labels/icons on a Canvas2D overlay, and runs a Preact UI in layout A (bottom tabs + pull-up sheets on iPhone, docked panel on iPad/PC). The world map is generated at build time from Natural Earth public-domain data into a compact binary plus a states JSON, committed to the repo.

**Tech Stack:** TypeScript (strict), Vite, Preact + @preact/signals, raw WebGL2, Vitest, @playwright/test **1.63.0** (must match the pre-installed Chromium), vite-plugin-pwa, fake-indexeddb (tests), tsx (build scripts), ESLint with typescript-eslint. Use the current stable version of each other package and commit `package-lock.json`.

**Spec:** `docs/superpowers/specs/2026-11-17-iron-and-gold-design.md`

## Global Constraints

- No nukes or nuke-like weapons anywhere, ever.
- Runs in iOS Safari (current and previous major) and desktop Chrome, Edge, Safari, Firefox; installable to the Home Screen, full screen, offline.
- Simulation is deterministic: no `Math.random`, `Date.now`, `performance.now`, `Math.sin/cos/tan/atan2/exp/log/pow/hypot`, or unordered iteration in `src/sim/**`; only `+ - * /`, `Math.sqrt/floor/ceil/round/min/max/abs/trunc` and integer ops. Randomness only from the seeded RNG stored in `GameState`. Enforced by ESLint (Task 3).
- Every player and AI action is a serializable `Command` applied by `step()`; the AI never mutates state directly.
- Content (countries, start dates, buildings, goods, personalities) lives in data modules under `src/content/`, not engine code.
- All storage names (IndexedDB, localStorage keys, Cache Storage) start with `iron-and-gold-`.
- Built site works under the base path `/<repo-name>/` (GitHub reports the repo as `Bodrid/Iron-and-gold`; paths are case-sensitive). Base path comes from env var `BASE_PATH`, default `/`.
- Tap targets ≥ 44 CSS px; no hover-only interactions; nothing under the Dynamic Island or home bar (safe-area insets) in either landscape direction.
- iPhone is landscape-only (portrait shows a "turn your phone sideways" screen); iPad works in both orientations and split view.
- Steady 60 fps map rendering on iPad Air (5th gen, M1) and iPhone 17 Pro; simulation keeps up at speed 3.
- Pacing: 1 tick = ¼ game day (`TICKS_PER_DAY = 4`); speeds 1/2/3 = 8/12/24 ticks per real second (≈3 min / 2 min / 1 min per game year); 1836 start runs to 1 Jan 1936.
- Early win: player holds ≥ 50% of all land tiles.
- AI levels: Easy, Normal, Hard, Very Hard, Grand Master; only Grand Master gets bonuses, shown on the difficulty screen.
- Map grid: equirectangular, width `2400`, latitudes `+80` to `−56` (height `907`), no east–west wrap, Antarctica excluded.
- The repo's own `main` branch is what Pages deploys; commit work to `main` only if the owner allowed it at execution time, otherwise to the session's working branch.

## Review Focus

1. **iOS kills the backgrounded Home Screen app mid-game** → reopening offers Continue from a save made when the app was hidden (test in Task 19).
2. **A country loses all its land mid-war** (player or AI) → it's removed from wars, attacks, labels and lists; the player sees a defeat screen; nothing throws (tests in Task 5 and Task 18).
3. **Rapid repeated taps on Build or Attack** → duplicate commands never overspend, exceed slots, or attack with troops you no longer have; `step()` validates every command (tests in Task 4 and Task 6).
4. **Rotating the device, iPad split view, iPhone held upright** → canvas resizes without stretching, layout switches between sheet and dock, iPhone portrait shows the rotate screen (test in Task 16).
5. **Huge simultaneous fronts at speed 3** (many wars plus colonisation everywhere) → tile updates to the main thread are coalesced into bounded messages and the UI keeps responding (test in Task 12).

```ts
export const enum Terrain { Sea = 0, Lake = 1, Plains = 2, Forest = 3, Hills = 4, Mountains = 5, Desert = 6 }
export const TERRAIN_MASK = 0x0f, RIVER_BIT = 0x80, COAST_BIT = 0x40; // in terrain byte
export interface StateDef {
  id: number;            // 1..n, 0 = no state (sea/lake)
  key: string;           // stable, e.g. "DEU-Bayern"
  name: string; modern: string;          // modern = ISO adm0_a3
  tiles: number; coastal: boolean;
  centroid: [number, number];            // tile coords
  neighbors: number[];                   // state ids sharing a land border, ascending
  resources: { coal: boolean; iron: boolean; fertility: number; forest: number }; // fertility/forest 0..1
  popWeight: number;
}
export interface MapData { width: number; height: number; terrain: Uint8Array; stateOf: Uint16Array; states: StateDef[] /* index = id, [0] unused */; landTiles: number; }
export function encodeGrid(m: Pick<MapData,'width'|'height'|'terrain'|'stateOf'>): Uint8Array; // "IGM1", u16 version=1, u16 w, u16 h, terrain[w*h], stateOf[w*h] LE
export function decodeGrid(bytes: Uint8Array): Pick<MapData,'width'|'height'|'terrain'|'stateOf'>;
export function assembleMap(grid, states: StateDef[]): MapData;   // computes landTiles
export async function loadMap(baseUrl: string): Promise<MapData>; // fetch world.igm.gz via DecompressionStream('gzip') + states.json
export function makeTestWorld(spec: string[], opts?: { coastal?: boolean }): MapData;
```
`makeTestWorld(rows, opts?)` takes rows of characters: `.` sea, `~` lake, `p` plains, `f` forest, `h` hills, `m` mountains, `d` desert, uppercase `A`–`Z` = plains belonging to state `T-<letter>`. Each 4-connected region of one lowercase terrain letter is its own state `T-<letter><n>` (n from 1). State ids are assigned by first appearance in row-major order; `modern` is `TST` for all. Coast bits, neighbours, centroids and `landTiles` are computed; resources default to `{ coal: false, iron: false, fertility: 1, forest: 0 }` unless `opts.resources` maps keys to overrides.

### Task 4: Troops and OpenFront-style attacks (including unclaimed land)

**Files:**

**Interfaces:**
- Consumes: `GameState`, `setTile`, `tileHash`, `BALANCE`.
- Produces:
```ts
export function recomputeMaxTroops(state: GameState, c: Country): void;   // population × MANPOWER_SHARE + barracks levels × BARRACKS_TROOPS
export function dailyTroops(state: GameState, c: Country): void;          // refill toward max, consumes arms
export function launchAttack(state: GameState, cmd: Extract<Command,{type:'attack'}>): SimEvent | null; // null = ok, else rejected event
export function combatTick(state: GameState, changed: number[], events: SimEvent[]): void;
export function canAttack(state: GameState, attacker: CountryId, target: CountryId): boolean; // target 0 always (if bordering); others only when at war
export function sharesBorder(state: GameState, a: CountryId, b: CountryId): boolean;
```
Rules (constants in `BALANCE.combat` / `BALANCE.troops`; values are the builder's to tune, behaviour is fixed):
- Launch: `troops = floor(country.troops × ratio)`; reject if ratio ∉ [0.01, 1], troops < `MIN_ATTACK_TROOPS`, no shared border (by controlled tiles), or `!canAttack`. Troops leave the pool immediately. Several attacks on the same target merge into one.
- Each tick an attack takes up to `clamp(floor(troops / TROOPS_PER_TILE_RATE), 1, MAX_TILES_PER_TICK)` frontier tiles: target-controlled tiles 4-adjacent to attacker-controlled tiles, cheapest first, ties by `tileHash(tile, state.tick)`.
- Tile cost = `TERRAIN_COST[terrain] × (river ? RIVER_MULT : 1) × (fort in state ? FORT_MULT : 1) × (1 + defenderDensity / DENSITY_REF)`, where `defenderDensity = defender.troops / defender.tiles` (0 for unclaimed). Attacker pays the cost; defender loses `min(defender.troops, defenderDensity × DEFENDER_LOSS)`. Casualties are added to the war's `casualties`.
- Unclaimed tiles become owned and controlled by the attacker. Enemy tiles become **controlled** by the attacker, owner unchanged; retaking your own occupied tile restores control.
- An attack ends when it can't pay the next tile or has no frontier; leftover troops return to the pool.
- Daily refill: `troops += (maxTroops − troops) × REFILL_RATE × armsFactor × railwayBarracksBonus`, where `armsFactor = 1` if the country has arms in stock (consumes `refilled / TROOPS_PER_ARMS` arms), else `NO_ARMS_FACTOR` (0.4).

- Grand Master bonuses apply through the sim (refill, build cost, research) and nowhere else.
